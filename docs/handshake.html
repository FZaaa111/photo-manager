TLS 1.3 与 REALITY 握手

逐条报文拆开两种握手：标准 TLS 1.3 如何在一个往返内协商密钥并验证服务器身份；REALITY 作为一种 TLS 伪装方案，如何复用真实网站的证书外观，并把自定义认证信息放进握手字段里。点击时序图中任意一行，或用键盘 ← → 逐步查看。

两种握手的差别

标准 TLS 1.3REALITY
服务端身份CA 签发的证书链，配合 CertificateVerify 签名握手时即时生成的临时证书，签名位由预共享密钥派生，不经过任何 CA
客户端身份通常不认证（可选客户端证书）放在握手字段里的一段密文，服务端据此判断客户端是否已知
预共享信息系统内置的根证书服务端公钥、短标识、借用的站点名，双方事先配置好
SNI 中的域名服务器自己的域名借用的目标站点域名，例如 www.example-cdn.com
需要自己的域名需要不需要
协议前提—必须 TLS 1.3 + X25519；目标站点也需支持，否则无法对齐外观

为什么前提是 TLS 1.3

TLS 1.2 的 Certificate 消息是明文，旁观者能直接读到证书内容。TLS 1.3 从 ServerHello 之后即开始加密，证书对旁观者不可见，这是 REALITY 能出示一张自备临时证书的基础。

为什么握手字段能携带数据

TLS 1.3 中 legacy_session_id 仅为兼容中间设备而保留，客户端通常填 32 字节随机数。一段 AEAD 密文在统计上同样接近均匀随机，放在这里不改变报文的外观分布。

REALITY 对齐不了什么

目的 IP 与域名的对应关系。握手里写着某个大站的域名，连接却指向另一台主机，这种不一致是其固有特征。

REALITY 部分依据 XTLS/REALITY 的公开设计整理，字段与校验细节可能随版本调整；示例域名与数值均为占位。TLS 1.3 部分依据 RFC 8446。本页用于协议教学。
